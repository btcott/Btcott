# Дизайн рабочей среды: Claude Code и мобильная разработка на Expo

Дата: 07.11.2026

## Цель

На новом Mac одна команда `./install.sh` разворачивает готовую среду. После неё можно создать Expo-приложение и работать над ним с Claude Code.

Код приложений в основном пишет Claude Code: опыта программирования у владельца почти нет.

## Критерии успеха

- Повторный запуск скрипта ничего не ломает.
- От пользователя требуются только действия, которые нельзя автоматизировать: вход в аккаунты, установка Xcode и настройка Android SDK.
- В репозитории нет секретов.
- Приёмочная проверка из раздела «Тестирование» проходит полностью.

## Выбор технологии

Приложения под iPhone и Android из одной кодовой базы делаем на **Expo (React Native + TypeScript)**.

| | Expo (выбран) | Flutter | React Native без Expo |
|---|---|---|---|
| Язык | TypeScript | Dart | TypeScript |
| Порог входа | Низкий | Средний | Высокий |
| Плюсы | Самая большая экосистема, облачная сборка EAS, простая проверка на своём iPhone | Единый набор инструментов, свой рендеринг, фреймворк бесплатный | Полный контроль над нативной частью |
| Минусы | SDK часто обновляется, у облачной сборки есть платные тарифы | Меньше сообщество, слабее веб-версия | Ручная настройка Xcode и Gradle, ошибки сложнее для новичка |

Причины выбора: Expo чаще других советуют новичкам и разработчикам-одиночкам, EAS берёт на себя сборку и подпись, а TypeScript пригодится и вне мобильной разработки.

Данные сравнения взяты в основном из блогов. Актуальные версии инструментов проверяются по официальной документации перед настройкой.

Для публикации в App Store нужен Apple Developer Program, около 99 $ в год.

## Архитектура

```
dotfiles/
├── install.sh        # точка входа: Homebrew, пакеты, симлинки
├── Brewfile          # Node, gh и другие инструменты
├── .zshrc
├── .gitignore        # не даёт закоммитить секреты и ключи
├── .github/
│   └── workflows/
│       └── install.yml  # чистая установка, ручной запуск
├── claude/
│   ├── CLAUDE.md     # глобальные правила
│   └── settings.json # настройки Claude Code
├── commands/         # slash-команды
├── scripts/          # statusline.sh
├── tests/
│   └── test-install.sh  # проверки install.sh во временном HOME
└── docs/
    ├── project-design.md
    └── project-implementation.md
```

Три слоя:

1. **Базовый:** Homebrew, zsh и git.
2. **Claude Code:** правила, настройки, команды и statusline, общие для всех проектов.
3. **Мобильный:** Node, Xcode с симулятором, EAS CLI.

Сознательно не делаем: Ansible, Nix, менеджеры dotfiles вроде chezmoi, шаблон приложения и hooks. Hooks появятся, когда возникнет конкретная повторяющаяся проблема.

## Компоненты

### Слой Claude Code

- **`CLAUDE.md`:** текущая локаль и правила работы: не коммитить секреты, в `main` не пушить без прямой просьбы, после изменений запускать проверки.
- **`settings.json`:** текущие настройки, плагины и statusline.
- **`permissions.deny`:** запрет чтения `.env`, `~/.ssh` и файлов с ключами. Он нужен, потому что алиас `claude` отключает запросы разрешений.
- **Команды:** `/edit-global-rules` и новая `/expo-check`. Она запускает проверку типов, линтер, тесты и `expo-doctor`, а затем кратко сообщает о проблемах.

### Мобильный слой

В `Brewfile`:

| Инструмент | Зачем |
|---|---|
| `node` | Запуск Expo и инструментов; Expo SDK 58 требует Node 22.13 или новее |
| `gh`, `jq` | Работа с GitHub, statusline |
| JDK `zulu@17` | Сборка под Android |
| `android-studio` | Эмулятор Android и SDK |
| `shellcheck`, `gitleaks` | Проверка скриптов и поиск секретов |

Вне `Brewfile`:

- **Xcode** ставится вручную из App Store.
- **Expo CLI** не ставится глобально: запускается через `npx expo`, поэтому версия соответствует проекту.
- **EAS CLI** ставится глобально через npm, потому что нужен вне конкретного проекта.
- **`JAVA_HOME`, `ANDROID_HOME` и `PATH`** прописываются в `.zshrc`.
- **Watchman** не нужен: Expo требует его только для SDK 55 и старше.

Проверка приложений: в повседневной разработке на iOS-симуляторе и Android-эмуляторе, перед релизом на реальных устройствах через сборку EAS.

## Поток выполнения `install.sh`

Каждый шаг сначала проверяет, сделан ли он уже.

Режим `./install.sh --links-only` выполняет только проверку системы и симлинки, без установки программ. Он нужен для тестов и для быстрого обновления симлинков.

Режим `./install.sh --check` ничего не меняет и только показывает, какие ручные шаги остались. Он нужен для тестов и для проверки после ручной настройки.

1. **Проверка:** это macOS, репозиторий лежит в `~/dotfiles`.
2. **Command Line Tools:** если их нет, запускается установка, и скрипт просит запустить его снова после её завершения.
3. **Homebrew:** ставится официальным установщиком, если его ещё нет.
4. **Пакеты:** `brew bundle` ставит всё из `Brewfile`.
5. **Симлинки:** `.zshrc`, `CLAUDE.md`, `settings.json`, `statusline.sh` и команды.
6. **Claude Code:** ставится, если команды `claude` нет.
7. **Итог:** только те ручные шаги, которые ещё не выполнены.

Ручные шаги, которые скрипт только перечисляет:

- установить Xcode и принять лицензию: `sudo xcodebuild -license accept`;
- поставить iOS runtime: Xcode → Settings → Components → Platform Support → iOS → Get;
- открыть Android Studio, пройти мастер первого запуска и установить Android SDK Platform 36, Sources for Android 36, Build-Tools и Android Emulator;
- создать виртуальное устройство в Device Manager;
- войти в аккаунты: `claude`, `gh auth login`, `eas login`.

## Обработка ошибок

- `set -Eeuo pipefail`: при первой ошибке скрипт останавливается и пишет, на каком шаге. После исправления его можно запустить снова, готовые шаги пропустятся.
- Симлинки никогда не затирают файлы: существующий файл сначала переносится в `~/.dotfiles-backup/<дата-время>/`.

## Безопасность

- Скрипт не запрашивает и не хранит пароли и токены.
- `sudo` вызывает только установщик Homebrew.
- Репозиторий публичный, поэтому токены и ключи в него не попадают: они лежат только локально и не отслеживаются git. Для токенов и личных настроек предназначен `~/.zshrc.local`: `.zshrc` подключает его, если файл есть.
- `permissions.deny` защищает от случайного чтения, но не от намеренного. При `--dangerously-skip-permissions` проверка показала: инструмент Read и `cat` заблокированы, а `python3 -c "open('.env')"` читает файл.

## Тестирование

### Перед каждым коммитом

- `shellcheck` для `install.sh` и `scripts/*.sh`.
- `jq` проверяет, что `settings.json` остаётся валидным JSON.
- `gitleaks` ищет секреты в репозитории.

### Проверки `install.sh`

| Сценарий | Ожидаемый результат |
|---|---|
| Повторный запуск на настроенном Mac | Ничего не меняется, бэкапы не создаются |
| На месте симлинка лежит обычный файл | Файл перенесён в бэкап, симлинк создан |
| Ошибка на середине, затем повторный запуск | Скрипт продолжает работу без поломок |
| Чистая установка | Вся среда разворачивается, остаются только ручные шаги |

Первые три сценария прогоняются локально с временным `HOME`, чтобы не задеть настоящие файлы.

Чистая установка проверяется в GitHub Actions на `macos-latest` с ручным запуском, только для `Brewfile` и симлинков. Xcode и вход в аккаунты там не проверить.

### Приёмка

1. Создать тестовое приложение: `npx create-expo-app`.
2. Запустить его на iOS-симуляторе и Android-эмуляторе.
3. Выполнить `/expo-check` в Claude Code.
4. Удалить тестовое приложение.

Если все четыре шага прошли, среда считается готовой.

## Открытые вопросы

- **Statusline.** Показывает ли он заполненность контекста в живой сессии: имя поля `context_window.used_percentage` пока не подтверждено.
- **Android Studio.** Занимает много места. Если эмулятор не понадобится, приложение можно проверять на телефоне с Android.

## Проверено при реализации

- **Симлинк `settings.json`.** Запись через `claude plugin disable` сохраняет симлинк и меняет исходный файл, поэтому копия не нужна. Проверен только этот способ записи.
- **`permissions.deny`.** Запреты работают при `--dangerously-skip-permissions`, с ограничением из раздела «Безопасность».
